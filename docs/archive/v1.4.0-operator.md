## 2. Job Reconciliation Loop ✅

### Reconciliation Cycle

**Every 30 seconds:**

1. **QUEUED jobs** → Attempt worker assignment
2. **ASSIGNED jobs** → Check if worker started execution
3. **RUNNING jobs** → Update progress from worker events

### State Transitions

```
CREATED (on create)
  ↓ (validate)
VALIDATED
  ↓ (queue)
QUEUED
  ↓ (reconcile: assign)
ASSIGNED
  ↓ (reconcile: check start)
RUNNING
  ↓ (reconcile: update progress)
PROGRESSING
  ↓ (worker completes)
COMPLETED / FAILED / CANCELLED
```

### Reconciliation Logic

```python
async def reconcile_migration_job(name, namespace, spec, status):
    state = status.get('state')

    if state == JobState.QUEUED:
        # Try to assign to worker
        await assign_to_worker(namespace, name, spec, status)

    elif state == JobState.ASSIGNED:
        # Check if worker started the job
        worker = status.get('assignedWorker')
        if check_job_running(namespace, worker, name):
            update_status(state=JobState.RUNNING)

    elif state == JobState.RUNNING:
        # Update progress from worker events
        await update_job_progress(namespace, name, status)
```

## 4. Job Assignment Algorithm ✅

### Scoring System (0-100 points)

| Factor | Max Points | Description |
|--------|------------|-------------|
| **Capabilities** | 40 | Worker supports required operations |
| **Load** | 30 | Worker has fewer active jobs |
| **Priority** | 20 | High-priority jobs prefer idle workers |
| **Affinity** | 10 | Worker matches job's workerSelector |

**Total:** 100 points maximum

### Scoring Examples

**Scenario 1: High-priority job, idle worker**
- Capabilities: 40 (matches)
- Load: 30 (0 active jobs)
- Priority: 20 (high priority + idle)
- Affinity: 5 (partial match)
- **Total: 95 points**

**Scenario 2: Low-priority job, busy worker**
- Capabilities: 40 (matches)
- Load: 10 (2 active jobs)
- Priority: 10 (low priority)
- Affinity: 5 (partial match)
- **Total: 65 points**

**Scenario 3: Unsuitable worker**
- Capabilities: 0 (missing required format)
- **Total: 0 points** (rejected)

### Assignment Process

```python
async def assign_to_worker(namespace, name, spec, status):
    # 1. Discover workers
    workers = await discover_workers(namespace)

    # 2. Score each worker
    suitable_worker = await job_assigner.find_suitable_worker(
        spec=spec,
        workers=workers
    )

    if suitable_worker:
        # 3. Copy job spec to worker
        job_spec = create_job_spec(name, spec)
        await copy_job_to_worker(namespace, worker, name, job_spec)

        # 4. Start job on worker
        await start_job_on_worker(namespace, worker, name)

        # 5. Update status
        await update_job_status(
            namespace=namespace,
            name=name,
            state=JobState.ASSIGNED,
            assigned_worker=worker
        )

        # 6. Emit event
        await emit_event(
            namespace=namespace,
            name=name,
            reason="JobAssigned",
            message=f"Job assigned to worker {worker}"
        )
```

## Deployment

### Prerequisites

1. **Kubernetes cluster** (1.24+)
2. **Workers deployed** (DaemonSet or Deployment)
3. **CRD installed** (`kubectl apply -f k8s/operator/crds/migrationjob.yaml`)
4. **Operator image built** (`docker build --target operator -t hyper2kvm:operator .`)

### Step-by-Step Deployment

#### 1. Install CRD and RBAC

```bash
kubectl apply -f k8s/operator/crds/migrationjob.yaml
```

Verifies:
- CRD: `migrationjobs.hyper2kvm.io`
- Namespace: `hyper2kvm-system`
- ServiceAccount: `hyper2kvm-operator`
- ClusterRole + ClusterRoleBinding

#### 2. Build and Push Operator Image

```bash
# Build
docker build --target operator -t hyper2kvm:operator .

# For k3d
k3d image import hyper2kvm:operator -c your-cluster

# For kind
kind load docker-image hyper2kvm:operator --name your-cluster

# For remote registry
docker tag hyper2kvm:operator your-registry/hyper2kvm:operator
docker push your-registry/hyper2kvm:operator
```

#### 3. Deploy Operator

```bash
kubectl apply -f k8s/operator/deployment.yaml
```

Creates:
- Deployment: `hyper2kvm-operator` (1 replica)
- Service: Port 8080 (health check)
- ServiceMonitor: Prometheus integration (optional)

#### 4. Verify Operator

```bash
# Check pod status
kubectl get pods -n hyper2kvm-system

# Expected output:
# NAME                                   READY   STATUS    RESTARTS   AGE
# hyper2kvm-operator-abc123-xyz          1/1     Running   0          30s

# Check logs
kubectl logs -n hyper2kvm-system -l app=hyper2kvm-operator -f

# Expected: "Starting Hyper2KVM Kubernetes Operator v1.4.0"
```

## Troubleshooting

### Operator Not Starting

**Symptom:** Operator pod CrashLoopBackOff

**Check:**
```bash
kubectl logs -n hyper2kvm-system -l app=hyper2kvm-operator
```

**Common Issues:**
- Missing CRD: Install with `kubectl apply -f k8s/operator/crds/migrationjob.yaml`
- RBAC permissions: Verify ClusterRoleBinding exists
- Image pull error: Check image name and availability

### Jobs Stuck in QUEUED

**Symptom:** MigrationJob state remains QUEUED

**Check:**
```bash
# Check if workers are running
kubectl get pods -n hyper2kvm-workers -l app=hyper2kvm-worker

# Check operator logs
kubectl logs -n hyper2kvm-system -l app=hyper2kvm-operator -f
```

**Common Issues:**
- No workers available (check DaemonSet/Deployment)
- Workers not ready (check worker pod status)
- Worker label mismatch (verify `app=hyper2kvm-worker` label)

### Status Not Updating

**Symptom:** MigrationJob status not reflecting actual state

**Check:**
```bash
# Check if operator can update CRD status
kubectl get migrationjob -n hyper2kvm-workers -o yaml

# Check operator logs for errors
kubectl logs -n hyper2kvm-system -l app=hyper2kvm-operator | grep -i error
```

**Common Issues:**
- Operator lacks RBAC permissions (check ClusterRole)
- API server timeout (check cluster health)
- Worker pod gone (operator will reassign)
