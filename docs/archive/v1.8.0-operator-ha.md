## 1. Leader Election Overview ✅

### Architecture

```
┌─────────────────────────────────────────────────────────┐
│ 3 Operator Replicas (replicaCount: 3)                  │
│                                                          │
│ ┌──────────┐  ┌──────────┐  ┌──────────┐              │
│ │ Pod 1    │  │ Pod 2    │  │ Pod 3    │              │
│ │ LEADER   │  │ STANDBY  │  │ STANDBY  │              │
│ │ ●        │  │ ○        │  │ ○        │              │
│ └────┬─────┘  └────┬─────┘  └────┬─────┘              │
│      │             │             │                       │
└──────┼─────────────┼─────────────┼───────────────────────┘
       │             │             │
       │             │             │
       ▼             ▼             ▼
┌─────────────────────────────────────────────────────────┐
│ Kubernetes Lease (coordination.k8s.io/v1)              │
│                                                          │
│ name: hyper2kvm-operator-leader                         │
│ holder: pod-1                                           │
│ renewTime: 2026-01-30T10:15:30Z                        │
│ leaseDuration: 15s                                      │
│ leaseTransitions: 2                                     │
└─────────────────────────────────────────────────────────┘
```

### How It Works

1. **Election**: All replicas attempt to acquire the lease
2. **Leadership**: First replica to acquire lease becomes leader
3. **Renewal**: Leader renews lease every 2 seconds (retry period)
4. **Standby**: Non-leader replicas watch the lease
5. **Failover**: If leader fails to renew within 15 seconds, standby takes over

### Key Characteristics

- **Single Leader**: Only one replica actively reconciles resources
- **Fast Failover**: New leader elected within ~5 seconds of failure
- **Automatic Recovery**: No manual intervention required
- **Resource Efficient**: Standby replicas consume minimal resources
- **Zero Downtime**: Leader transitions are transparent to users

## 2. Configuration ✅

### Helm Values

**Enable Leader Election:**
```yaml
# values.yaml
operator:
  # Number of replicas (HA requires 2+)
  replicaCount: 3

  # Leader election configuration
  leaderElection:
    # Enable leader election
    enabled: true

    # Lease name
    leaseName: "hyper2kvm-operator-leader"

    # Lease duration (seconds)
    # How long leader holds the lease
    leaseDuration: 15

    # Renew deadline (seconds)
    # How long leader has to renew before losing leadership
    renewDeadline: 10

    # Retry period (seconds)
    # How often to attempt renewal/acquisition
    retryPeriod: 2
```

### Parameter Tuning

**Conservative (stable, slower failover):**
```yaml
leaderElection:
  leaseDuration: 30
  renewDeadline: 20
  retryPeriod: 5
```
- Failover time: ~30-35 seconds
- Lease churn: Low
- Network resilience: High

**Aggressive (fast failover, more sensitive):**
```yaml
leaderElection:
  leaseDuration: 10
  renewDeadline: 7
  retryPeriod: 1
```
- Failover time: ~10-15 seconds
- Lease churn: Higher
- Network resilience: Lower

**Recommended Production:**
```yaml
leaderElection:
  leaseDuration: 15
  renewDeadline: 10
  retryPeriod: 2
```
- Failover time: ~15-20 seconds
- Lease churn: Moderate
- Network resilience: Good balance

## 3. Deployment Guide ✅

### Basic HA Deployment

```bash
# Install operator with 3 replicas
helm install hyper2kvm-operator hyper2kvm/hyper2kvm-operator \
  --namespace hyper2kvm-system \
  --create-namespace \
  --set operator.replicaCount=3 \
  --set operator.leaderElection.enabled=true
```

### Production HA Deployment

**Create production values:**
```yaml
# production-ha-values.yaml
operator:
  replicaCount: 3

  # Anti-affinity to spread across nodes
  affinity:
    podAntiAffinity:
      preferredDuringSchedulingIgnoredDuringExecution:
      - weight: 100
        podAffinityTerm:
          labelSelector:
            matchLabels:
              app.kubernetes.io/component: operator
          topologyKey: kubernetes.io/hostname

  # Resource allocation
  resources:
    requests:
      cpu: 200m
      memory: 256Mi
    limits:
      cpu: 1000m
      memory: 1Gi

  # Leader election
  leaderElection:
    enabled: true
    leaseDuration: 15
    renewDeadline: 10
    retryPeriod: 2

  # Metrics for monitoring
  metrics:
    enabled: true
    serviceMonitor:
      enabled: true

# Webhook also HA
webhook:
  enabled: true
  replicaCount: 3

  # Webhook anti-affinity
  affinity:
    podAntiAffinity:
      preferredDuringSchedulingIgnoredDuringExecution:
      - weight: 100
        podAffinityTerm:
          labelSelector:
            matchLabels:
              app.kubernetes.io/component: webhook
          topologyKey: kubernetes.io/hostname
```

**Install:**
```bash
helm install hyper2kvm-operator hyper2kvm/hyper2kvm-operator \
  --namespace hyper2kvm-system \
  --create-namespace \
  --values production-ha-values.yaml
```

### Verify HA Deployment

```bash

kubectl get pods -n hyper2kvm-system -l app.kubernetes.io/component=operator

# Expected output:
```

```bash

  -o jsonpath='{.spec.holderIdentity}')
```

| `hyper2kvm_operator_leader_election_enabled` | Gauge | Whether leader election is enabled (1=yes, 0=no) |

```promql
hyper2kvm_operator_leader_election_enabled == 1
```

## 6. Troubleshooting ✅

### No Leader Elected

**Symptoms:**
- Lease exists but no holder
- All replicas show as standby
- Jobs not being reconciled

**Diagnosis:**
```bash
# Check lease status
kubectl get lease -n hyper2kvm-system hyper2kvm-operator-leader -o yaml

# Check RBAC permissions
kubectl auth can-i get leases \
  --as=system:serviceaccount:hyper2kvm-system:hyper2kvm-operator \
  -n hyper2kvm-system

kubectl auth can-i create leases \
  --as=system:serviceaccount:hyper2kvm-system:hyper2kvm-operator \
  -n hyper2kvm-system

# Check operator logs
kubectl logs -n hyper2kvm-system -l app.kubernetes.io/component=operator \
  --tail=50 | grep -i "leader\|lease"
```

**Solution:**
1. Verify RBAC permissions for leases
2. Check for API server connectivity issues
3. Review operator logs for errors
4. Restart all operator replicas

### Multiple Leaders (Split Brain)

**Symptoms:**
- Multiple replicas claim to be leader
- Duplicate job assignments
- Conflicting status updates

**Diagnosis:**
```bash
# Check logs from all replicas
for pod in $(kubectl get pods -n hyper2kvm-system \
  -l app.kubernetes.io/component=operator -o name); do
  echo "=== $pod ==="
  kubectl logs -n hyper2kvm-system $pod --tail=20 | grep "became leader"
done

# Check lease holder
kubectl get lease -n hyper2kvm-system hyper2kvm-operator-leader \
  -o jsonpath='{.spec.holderIdentity}'
```

**Solution:**
1. Delete the lease to force re-election:
   ```bash
   kubectl delete lease hyper2kvm-operator-leader -n hyper2kvm-system
   ```
2. Restart all operator replicas
3. Check for clock skew on cluster nodes

### Frequent Leader Changes

**Symptoms:**
- High lease transition count
- Unstable leadership
- Performance degradation

**Diagnosis:**
```bash
# Check transition rate
kubectl get lease -n hyper2kvm-system hyper2kvm-operator-leader \
  -o jsonpath='{.spec.leaseTransitions}'

# Check renewal failures
kubectl port-forward -n hyper2kvm-system deployment/hyper2kvm-operator 8080:8080 &
curl -s http://localhost:8080/metrics | grep lease_renewal

# Check network latency
kubectl exec -n hyper2kvm-system deployment/hyper2kvm-operator -- \
  time kubectl get lease hyper2kvm-operator-leader
```

**Solution:**
1. Increase lease duration and renew deadline:
   ```yaml
   leaderElection:
     leaseDuration: 30
     renewDeadline: 20
     retryPeriod: 5
   ```
2. Check network stability
3. Check API server load
4. Review pod resource limits

### Slow Failover

**Symptoms:**
- Long delay before new leader elected
- Jobs stalled during failover

**Diagnosis:**
```bash
# Simulate failover and measure time
BEFORE=$(date +%s)
LEADER=$(kubectl get lease -n hyper2kvm-system hyper2kvm-operator-leader \
  -o jsonpath='{.spec.holderIdentity}')

kubectl delete pod "$LEADER" -n hyper2kvm-system

# Wait for new leader
while true; do
  NEW_LEADER=$(kubectl get lease -n hyper2kvm-system hyper2kvm-operator-leader \
    -o jsonpath='{.spec.holderIdentity}' 2>/dev/null)
  if [ -n "$NEW_LEADER" ] && [ "$NEW_LEADER" != "$LEADER" ]; then
    AFTER=$(date +%s)
    echo "Failover time: $((AFTER - BEFORE)) seconds"
    echo "New leader: $NEW_LEADER"
    break
  fi
  sleep 1
done
```

**Solution:**
1. Decrease lease duration for faster detection:
   ```yaml
   leaderElection:
     leaseDuration: 10
     renewDeadline: 7
     retryPeriod: 1
   ```
2. Increase operator replicas for faster takeover
3. Optimize pod startup time

## 7. Best Practices ✅

### Replica Count

**Development:**
- 1 replica with leader election disabled
- Fastest startup, minimal resources

**Staging:**
- 2 replicas with leader election enabled
- Basic HA testing

**Production:**
- 3+ replicas with leader election enabled
- Survives 1-2 node failures
- Spread across availability zones

### Pod Anti-Affinity

**Recommended:**
```yaml
affinity:
  podAntiAffinity:
    preferredDuringSchedulingIgnoredDuringExecution:
    - weight: 100
      podAffinityTerm:
        labelSelector:
          matchLabels:
            app.kubernetes.io/component: operator
        topologyKey: kubernetes.io/hostname
```

**Strict (requires 3+ nodes):**
```yaml
affinity:
  podAntiAffinity:
    requiredDuringSchedulingIgnoredDuringExecution:
    - labelSelector:
        matchLabels:
          app.kubernetes.io/component: operator
      topologyKey: kubernetes.io/hostname
```

### Resource Allocation

```yaml
resources:
  requests:
    cpu: 200m      # Minimum for smooth operation
    memory: 256Mi  # Sufficient for most workloads

  limits:
    cpu: 1000m     # Allow burst for reconciliation
    memory: 1Gi    # Prevent OOM
```

### Monitoring

**Essential Alerts:**
```yaml
# No leader elected for 5 minutes
- alert: OperatorNoLeader
  expr: sum(hyper2kvm_operator_is_leader) == 0
  for: 5m
  annotations:
    summary: "No operator leader elected"

# Frequent leader changes
- alert: OperatorFrequentFailovers
  expr: rate(hyper2kvm_operator_leader_transitions_total[1h]) > 0.1
  for: 30m
  annotations:
    summary: "Operator leader changing too frequently"

# Lease renewal failures
- alert: OperatorLeaseRenewalFailure
  expr: rate(hyper2kvm_operator_lease_renewal_total{result="failure"}[5m]) > 0.5
  for: 10m
  annotations:
    summary: "Operator failing to renew lease"
```

## 8. Upgrade from Single Replica ✅

### Zero-Downtime Upgrade

```bash
# Current: Single replica, no leader election
# Target: 3 replicas with leader election

# Step 1: Enable leader election (single replica)
helm upgrade hyper2kvm-operator hyper2kvm/hyper2kvm-operator \
  --namespace hyper2kvm-system \
  --set operator.replicaCount=1 \
  --set operator.leaderElection.enabled=true \
  --wait

# Step 2: Scale to 3 replicas
helm upgrade hyper2kvm-operator hyper2kvm/hyper2kvm-operator \
  --namespace hyper2kvm-system \
  --set operator.replicaCount=3 \
  --reuse-values \
  --wait

# Step 3: Verify all replicas are healthy
kubectl get pods -n hyper2kvm-system -l app.kubernetes.io/component=operator

# Step 4: Verify leader elected
kubectl get lease -n hyper2kvm-system hyper2kvm-operator-leader
```
