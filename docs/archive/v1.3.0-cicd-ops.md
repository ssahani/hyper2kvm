## 3. Operational Scripts ✅

**Location:** `scripts/ops/`

### Backup Worker State (backup-worker-state.sh)

Backs up worker state from Kubernetes cluster.

**Usage:**
```bash
./scripts/ops/backup-worker-state.sh [namespace] [output-dir]
```

**Example:**
```bash
./scripts/ops/backup-worker-state.sh hyper2kvm-workers /backup/$(date +%Y-%m-%d)
```

**What's Backed Up:**
- Worker job state (`/var/lib/hyper2kvm/jobs`)
- Event streams (`/var/lib/hyper2kvm/events`)
- Worker capabilities
- Pod metadata
- ConfigMaps
- PVC manifests
- DaemonSet configuration

**Output:**
```
worker-backup-2026-01-30-14-30-00/
├── worker-pod-1/
│   ├── job-001.json
│   ├── job-002.json
│   ├── events/
│   ├── capabilities.json
│   └── pod.yaml
├── worker-pod-2/
├── configmaps.yaml
├── pvcs.yaml
├── daemonset.yaml
└── backup-metadata.json

hyper2kvm-worker-backup-2026-01-30-14-30-00.tar.gz
```

**Features:**
- Automatic archiving
- Metadata tracking
- Per-pod backup
- Preserves all state

### Restore Worker State (restore-worker-state.sh)

Restores backed up state to workers.

**Usage:**
```bash
./scripts/ops/restore-worker-state.sh <backup-archive> [namespace]
```

**Example:**
```bash
./scripts/ops/restore-worker-state.sh \
  hyper2kvm-worker-backup-2026-01-30-14-30-00.tar.gz \
  hyper2kvm-workers
```

**Features:**
- Interactive confirmation
- Round-robin pod assignment
- Validates namespace exists
- Optional ConfigMap restore

**Safety:**
- Requires user confirmation
- Checks for running workers
- Preserves backup archive

### Migrate to Helm (migrate-to-helm.sh)

Migrates existing kubectl deployment to Helm-managed deployment.

**Usage:**
```bash
./scripts/ops/migrate-to-helm.sh [namespace]
```

**Example:**
```bash
./scripts/ops/migrate-to-helm.sh hyper2kvm-workers
```

**Migration Steps:**

1. **Backup current state** - Saves all resources
2. **Export configuration** - DaemonSet, ConfigMaps, PVCs
3. **Generate Helm values** - Extracts resource limits, image, node selector
4. **Delete DaemonSet** - Uses `--cascade=orphan` to preserve pods
5. **Install Helm chart** - Uses generated values
6. **Verify deployment** - Checks pods and Helm release

**Generated Helm Values:**
```yaml
# Generated from existing deployment
worker:
  image:
    repository: hyper2kvm
    tag: worker
  resources:
    requests:
      cpu: "2"
      memory: "4Gi"
    limits:
      cpu: "8"
      memory: "16Gi"
  nodeSelector:
    hyper2kvm.io/worker-enabled: "true"
storage:
  state:
    enabled: true
  # ... preserves existing PVCs
monitoring:
  metrics:
    enabled: true
```

**Benefits:**
- Seamless migration
- Zero downtime (orphaned pods)
- Preserves PVCs and state
- Backup safety net

## 4. Kubernetes Operator Foundation ✅

**Location:** `k8s/operator/`

### MigrationJob CRD

Custom Resource Definition for declarative job management.

**Installation:**
```bash
kubectl apply -f k8s/operator/crds/migrationjob.yaml
```

**Verify:**
```bash
kubectl get crd migrationjobs.hyper2kvm.io
kubectl api-resources | grep hyper2kvm
```

### Example MigrationJob

```yaml
apiVersion: hyper2kvm.io/v1alpha1
kind: MigrationJob
metadata:
  name: convert-windows-2019
  namespace: hyper2kvm-workers
spec:
  operation: convert

  image:
    path: /data/input/windows-2019.vmdk
    format: vmdk
    checksum: sha256:abc123...

  parameters:
    output_format: qcow2
    compress: true
    fstab_mode: stabilize-all
    regen_initramfs: true

  artifacts:
    output_path: /data/output
    output_format: qcow2
    compress: true

  priority: 75
  timeout: 2h

  retryPolicy:
    maxRetries: 2
    backoff: exponential

  workerSelector:
    hyper2kvm.io/gpu: "true"

status:
  state: Running
  assignedWorker: hyper2kvm-worker-abc123
  progress:
    percentage: 45
    currentPhase: "Converting disk image"
    message: "Processing partition 2/4"
```

### CRD Features

**Spec Fields:**
- `operation` - inspect, convert, offline_fix
- `image` - Source disk specification
- `parameters` - Operation-specific config
- `artifacts` - Output configuration
- `priority` - Job priority (0-100)
- `timeout` - Max execution time
- `retryPolicy` - Retry behavior
- `workerSelector` - Worker label selector

**Status Fields:**
- `state` - 10-state machine from Worker Protocol
- `assignedWorker` - Pod name
- `startTime`, `completionTime`
- `progress` - Real-time percentage and phase
- `result` - Output files and artifacts
- `retries` - Attempt counter
- `conditions` - Kubernetes-style conditions

**AdditionalPrinterColumns:**
```bash
kubectl get migrationjobs

NAME                     OPERATION   STATE      WORKER                   PROGRESS   AGE
convert-windows-2019     convert     Running    hyper2kvm-worker-abc123  45         5m
inspect-debian-12        inspect     Completed  hyper2kvm-worker-def456  100        1h
```

### Future Operator (v1.4.0+)

The CRD provides the foundation for a future operator controller:

**Controller Responsibilities:**
- Watch `MigrationJob` resources
- Assign jobs to workers based on capabilities
- Update `.status` automatically
- Stream progress events
- Implement retry logic
- Emit Kubernetes events

**Recommended Implementation:**
- **Kopf** (Python) - Easiest integration with hyper2kvm
- **Operator SDK** (Go) - Most mature
- **Kubebuilder** (Go) - Modern code generation

**See:** `k8s/operator/README.md` for detailed roadmap

### Operational Tasks

**Backup Before Upgrade:**
```bash
# Backup current state
./scripts/ops/backup-worker-state.sh hyper2kvm-workers /backups/pre-upgrade

# Upgrade Helm chart
helm upgrade hyper2kvm-worker ./helm/hyper2kvm-worker \
  --namespace hyper2kvm-workers \
  --values production-values.yaml

# If something goes wrong, restore
./scripts/ops/restore-worker-state.sh /backups/pre-upgrade/*.tar.gz
```

**Scheduled Backups:**
```bash
# Add to cron
0 2 * * * /path/to/scripts/ops/backup-worker-state.sh hyper2kvm-workers /backups/daily
```

**Migrate to Helm:**
```bash
# One-command migration
./scripts/ops/migrate-to-helm.sh hyper2kvm-workers

# Follow prompts, review generated values
```
