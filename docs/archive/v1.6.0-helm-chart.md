## 2. Installation Guide ✅

### Prerequisites

- Kubernetes 1.24+
- Helm 3.8+
- (Optional) Prometheus Operator for ServiceMonitor
- (Optional) cert-manager for automated TLS

### Quick Start

```bash
# Install with default configuration
helm install hyper2kvm-operator ./helm/hyper2kvm-operator \
  --namespace hyper2kvm-system \
  --create-namespace
```

### Custom Installation

**Create custom values file:**

```yaml
# production-values.yaml

# Operator configuration
operator:
  replicaCount: 1

  image:
    tag: "1.6.0"
    pullPolicy: IfNotPresent

  resources:
    requests:
      cpu: 200m
      memory: 256Mi
    limits:
      cpu: 1000m
      memory: 1Gi

  config:
    reconcileInterval: 30
    logLevel: INFO
    workerDiscoveryInterval: 60

  metrics:
    enabled: true
    serviceMonitor:
      enabled: true
      labels:
        prometheus: kube-prometheus

# Webhook configuration
webhook:
  enabled: true
  replicaCount: 3  # HA for production

  resources:
    requests:
      cpu: 100m
      memory: 128Mi
    limits:
      cpu: 500m
      memory: 512Mi

  config:
    maxJobsPerNamespace: 50  # Increase for large deployments
    validatingFailurePolicy: Fail
    mutatingFailurePolicy: Ignore

  tls:
    # Option 1: cert-manager (recommended)
    certManager:
      enabled: true
      issuerRef:
        name: letsencrypt-prod
        kind: ClusterIssuer

    # Option 2: Existing secret
    # existingSecret: "my-webhook-certs"

# Certificate job (disabled if using cert-manager)
certJob:
  enabled: false  # Set to true if not using cert-manager

# CRD configuration
crd:
  install: true
  keep: true  # Keep CRD on uninstall

# Monitoring
monitoring:
  prometheus:
    enabled: true
  grafana:
    enabled: true
    dashboardLabel: grafana_dashboard
  alerts:
    enabled: true

# Network policies
networkPolicy:
  enabled: true

# Pod Security Standards
podSecurityStandards:
  enabled: true
  enforce: baseline
  audit: restricted
  warn: restricted
```

**Install with custom values:**

```bash
helm install hyper2kvm-operator ./helm/hyper2kvm-operator \
  --namespace hyper2kvm-system \
  --create-namespace \
  --values production-values.yaml
```

## 3. Certificate Management ✅

### Option 1: Self-Signed Certificates (Default)

Automatic certificate generation using Helm hook:

```bash
# Certificates are automatically generated during install
helm install hyper2kvm-operator ./helm/hyper2kvm-operator \
  --namespace hyper2kvm-system \
  --create-namespace
```

**How it works:**
1. Helm pre-install hook triggers cert-job
2. Job generates CA certificate
3. Job generates server certificate (valid 10 years)
4. Job creates Kubernetes Secret
5. Job patches webhook configurations with CA bundle
6. Webhook deployment mounts certificate secret

**Certificate details:**
- CA: hyper2kvm-webhook-ca
- Server CN: hyper2kvm-operator-webhook.hyper2kvm-system.svc
- SANs: DNS names for service
- Validity: 3650 days (10 years, configurable)

### Option 2: cert-manager (Recommended for Production)

Automated certificate management with renewal:

**Prerequisites:**
```bash
# Install cert-manager
kubectl apply -f https://github.com/cert-manager/cert-manager/releases/download/v1.13.0/cert-manager.yaml

# Create self-signed issuer
cat <<EOF | kubectl apply -f -
apiVersion: cert-manager.io/v1
kind: ClusterIssuer
metadata:
  name: selfsigned-issuer
spec:
  selfSigned: {}
EOF
```

**Install operator with cert-manager:**

```yaml
# values.yaml
webhook:
  tls:
    certManager:
      enabled: true
      issuerRef:
        name: selfsigned-issuer
        kind: ClusterIssuer

certJob:
  enabled: false  # Disable cert-job
```

```bash
helm install hyper2kvm-operator ./helm/hyper2kvm-operator \
  --namespace hyper2kvm-system \
  --create-namespace \
  --values values.yaml
```

### Option 3: Existing Certificate Secret

Use your own certificates:

```bash
# Create certificate secret
kubectl create secret tls hyper2kvm-webhook-certs \
  --cert=path/to/tls.crt \
  --key=path/to/tls.key \
  --namespace hyper2kvm-system
```

```yaml
# values.yaml
webhook:
  tls:
    existingSecret: hyper2kvm-webhook-certs

certJob:
  enabled: false
```

## 6. Uninstalling ✅

### Uninstall Helm Release

```bash
# Uninstall operator
helm uninstall hyper2kvm-operator -n hyper2kvm-system

# CRDs are kept by default (helm.sh/resource-policy: keep)
# To remove CRDs manually:
kubectl delete crd migrationjobs.hyper2kvm.io

# Delete namespace
kubectl delete namespace hyper2kvm-system
```

### Cleanup MigrationJobs

```bash
# Delete all MigrationJobs across all namespaces
kubectl get migrationjobs --all-namespaces -o json | \
  jq -r '.items[] | "\(.metadata.namespace)/\(.metadata.name)"' | \
  while read job; do
    kubectl delete migrationjob ${job##*/} -n ${job%%/*}
  done
```

## 8. Production Considerations ✅

### Resource Sizing

**Small Deployment (< 50 jobs/day):**
```yaml
operator:
  resources:
    requests: {cpu: 100m, memory: 128Mi}
    limits: {cpu: 500m, memory: 512Mi}

webhook:
  replicaCount: 2
  resources:
    requests: {cpu: 100m, memory: 128Mi}
    limits: {cpu: 500m, memory: 512Mi}
```

**Medium Deployment (50-500 jobs/day):**
```yaml
operator:
  resources:
    requests: {cpu: 200m, memory: 256Mi}
    limits: {cpu: 1000m, memory: 1Gi}

webhook:
  replicaCount: 3
  config:
    maxJobsPerNamespace: 50
```

**Large Deployment (500+ jobs/day):**
```yaml
operator:
  resources:
    requests: {cpu: 500m, memory: 512Mi}
    limits: {cpu: 2000m, memory: 2Gi}
  config:
    maxConcurrentReconciles: 20

webhook:
  replicaCount: 5
  config:
    maxJobsPerNamespace: 100
```

### High Availability

```yaml
# Webhook HA (always on)
webhook:
  replicaCount: 3  # Minimum 2 for HA
  affinity:
    podAntiAffinity:
      preferredDuringSchedulingIgnoredDuringExecution:
      - weight: 100
        podAffinityTerm:
          labelSelector:
            matchLabels:
              app.kubernetes.io/component: webhook
          topologyKey: kubernetes.io/hostname

# Operator (leader election in future versions)
operator:
  replicaCount: 1
```

### Security Hardening

```yaml
# Pod Security Standards
podSecurityStandards:
  enabled: true
  enforce: restricted
  audit: restricted
  warn: restricted

# Network Policies
networkPolicy:
  enabled: true
  ingress:
    - from:
      - namespaceSelector:
          matchLabels:
            name: kube-system
  egress:
    - to:
      - namespaceSelector: {}
```

## 9. Troubleshooting ✅

### Operator Not Starting

```bash
# Check pods
kubectl get pods -n hyper2kvm-system -l app.kubernetes.io/component=operator

# View logs
kubectl logs -n hyper2kvm-system -l app.kubernetes.io/component=operator

# Check events
kubectl get events -n hyper2kvm-system --sort-by='.lastTimestamp'
```

### Webhook Certificate Issues

```bash
# Check cert-job logs
kubectl logs -n hyper2kvm-system -l job-name=hyper2kvm-operator-cert-job

# Verify secret
kubectl get secret -n hyper2kvm-system hyper2kvm-operator-webhook-certs

# Check CA bundle in webhook config
kubectl get validatingwebhookconfiguration hyper2kvm-operator-validating \
  -o jsonpath='{.webhooks[0].clientConfig.caBundle}' | base64 -d | openssl x509 -text

# Regenerate certificates
helm upgrade hyper2kvm-operator ./helm/hyper2kvm-operator \
  --namespace hyper2kvm-system \
  --recreate-pods
```

### Webhook Not Called

```bash
# Check webhook service
kubectl get svc -n hyper2kvm-system hyper2kvm-operator-webhook
kubectl get endpoints -n hyper2kvm-system hyper2kvm-operator-webhook

# Test webhook endpoint
kubectl port-forward -n hyper2kvm-system svc/hyper2kvm-operator-webhook 8443:443
curl -k https://localhost:8443/healthz

# Check namespace labels (webhooks skip control-plane namespaces)
kubectl get namespace hyper2kvm-system -o yaml | grep control-plane
```
